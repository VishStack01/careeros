DocsQuick start

Run CareerOS on your machine, with your own model.

CareerOS is a Python package (standard library only), a local dashboard and a set of agent skills. The AI steps use the provider and API key you choose. Everything else, including the job scan and every check, runs without a model.

Install

You need Python 3.11 or newer and git.

# get the code
git clone https://github.com/VishStack01/careeros.git
cd careeros

# install (add [browser] for the apply agent, [dev] for tests)
pip install -e .
careeros --version

Optional extras: pip install -e ".[browser]" then python -m playwright install chromium for the apply agent, and pip install pypdf to read resume PDFs.

Bring your own key

Copy .env.example to .env and fill in one provider. CareerOS reads .env from the folder you run it in; values already set in your shell win. The file is git-ignored.

cp .env.example .env
# then edit .env, for example:
CAREEROS_LLM=anthropic
ANTHROPIC_API_KEY=sk-ant-...

careeros llm          # shows provider and model, never the key
careeros llm test     # one tiny request to check it works
ProviderSetNotes
AnthropicCAREEROS_LLM=anthropic
ANTHROPIC_API_KEY		Claude models
OpenAICAREEROS_LLM=openai
OPENAI_API_KEY		Add OPENAI_BASE_URL for any OpenAI-compatible API: OpenRouter, Groq, Together, vLLM
Google GeminiCAREEROS_LLM=gemini
GEMINI_API_KEY		Gemini models
OllamaCAREEROS_LLM=ollama
OLLAMA_HOST (optional)		Free and fully local. No key, nothing leaves your machine

Pin models with CAREEROS_MODEL (every step) and CAREEROS_MODEL_QUICK (small steps). Without them CareerOS picks a sensible model per provider.

Your key is read from the environment at call time and sent only to the provider you chose. CareerOS never prints, logs or stores it, and the dashboard only accepts AI requests from its own page, so another website can't spend your key.

First run

careeros init                       # creates your private config files
careeros discover && careeros scan  # map company job boards and build the feed
careeros serve                      # dashboard at http://127.0.0.1:8765

Set your filters in config/settings.toml: target roles, experience limit, locations, posting window and pay floor. Your private files (config/*.toml, brain/, data/, .env) are git-ignored. careeros doctor checks the install and that nothing private is tracked.

Try the gates on any posting without a model:

careeros evaluate --company "Demo Co" --title "Junior AI Engineer" \
  --location "Remote, India" --mode remote --text-file posting.txt

AI commands

Each command drafts with your model, then code checks the draft before you see it.

careeros ai profile resume.pdf -o profile.json

Turns your resume into a structured profile. Any value the resume doesn't contain is removed and listed, so the model can't add a job, a tool or a number.

careeros ai posting posting.txt

Extracts company, title, pay, experience and requirements. A requirement is kept only if its quote appears in the posting.

careeros ai evaluate --jd posting.txt --resume resume.pdf -o eval.json

Scores fit from 1 to 5, requirement by requirement, with gaps and how to handle them. The draft must pass the same checks as careeros eval-check: verbatim quotes from the posting, the score inside its dimensions' range, a gap for every unmet critical requirement. If it fails, the model gets the errors once and tries again; if it fails twice, nothing is written. Use --brain brain.json to score against your Career Brain instead of the resume.

careeros ai evaluate --jd jd.txt --resume resume.pdf -o eval.json
careeros eval-check eval.json --jd jd.txt --md report.md

Dashboard

careeros serve opens the dashboard on 127.0.0.1 only. It shows fresh roles with the quotes behind every check, a daily batch to approve, applications by stage, inbox replies, follow-ups and referral notes. When a model is configured, the dashboard's AI actions (reading a posting, tailoring a resume and cover letter, importing your resume) run on it; without one, they fall back to rule-based versions.

Try it without installing: the live demo uses fictional data.

Job feed and API

An hourly GitHub Actions scan reads about 1,400 product companies' career pages through eight hiring systems and publishes a public feed. It contains public postings only.

Agents and skills

The repo ships agent skills for Claude Code (and instructions for Codex and others) in .claude/skills/: career-brain, job-scout, evaluate, tailor, reviewer, apply, tracker, outreach, coach, company-research and weekly-review. Open the folder in Claude Code and say "Use the career-brain skill" with your resume attached to start. Scheduled prompts for search, apply and inbox runs are in prompts/.

Privacy and safety

  • Your resume, profile, Career Brain and pipeline stay in local, git-ignored files.
  • No LinkedIn, Naukri, Indeed or Wellfound automation, no account creation and no captcha solving. Roles that only take applications there are marked "Apply yourself".
  • Messages and referral notes are drafted; you send them.
  • The apply agent submits only when it can answer every question from your saved details, and never twice.
Read the full responsible use notes before running the apply agent.

FAQ

Do I need an API key?

No. Scanning, filtering, tracking and the dashboard work without one. A key (or Ollama) adds the AI steps.

Which model should I use?

Any capable chat model works. Evaluations are long and strict, so a larger model passes the checks more often; small steps can use a cheaper model through CAREEROS_MODEL_QUICK.

What does it cost?

CareerOS is free and MIT licensed. You pay your provider for what your key uses, or nothing with Ollama.
